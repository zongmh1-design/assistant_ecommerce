# 项目范围

## 1. 项目目标

第一版面向中小电商团队，以一个具体商品为业务主线，提供可演示、可解释、可逐步扩展的运营工作台。系统负责保存业务数据、组织人工流程，并在明确边界内使用 AI 辅助生成结构化内容。

第一版的成功标准不是接入所有外部平台，而是能够用 Mock、示例数据和人工录入跑通完整的单品运营闭环。

## 2. 第一版做什么

### 基础能力

- 登录、当前用户识别和角色权限控制。
- 管理员、运营人员、查看人员三类角色。
- 店铺、商品及平台信息占位管理。
- 演示数据和必要的导入模板。

### 单品运营能力

- 创建店铺和商品，维护商品状态与所属店铺。
- 维护 SKU、库存数量、锁定库存、预警阈值和库存流水。
- 手工添加竞品，允许用公开信息、Mock 或示例数据补充竞品资料。
- 生成、编辑并保存结构化商品诊断。
- 为同一商品生成至少 3 个主图方案和至少 3 个视频脚本。
- 创建图片、视频素材生成任务，记录状态、失败原因、重试、取消、超时和事件。
- 将生成结果纳入素材库，并由人工审核后决定是否可用。
- 创建推广链接和追踪码，记录基础点击数据。
- 生成结构化投放建议，由有权限人员确认或驳回。
- 管理投放实验计划和结果，但不执行真实广告投放。
- 手工录入或通过 CSV / Excel 导入经营数据；导入支持预览、错误行提示和部分成功。
- 生成、编辑并保存经营分析报告和下一轮优化建议。

## 3. 第一版不做什么

- 不实现微服务、Kubernetes、Kafka、Redis Cluster、Elasticsearch、CQRS、Event Sourcing 或复杂 DDD。
- 不实现多 Agent 系统。
- 不真实连接淘宝、京东、抖音等平台账号和商品 API。
- 不保存平台明文密码、明文 Token、Cookie 或其他敏感凭据。
- 不实现绕过登录、验证码、风控或访问控制的采集逻辑。
- 不自动创建广告计划、修改真实预算、扣费或操作广告平台。
- 不构建复杂营销归因系统；推广链路只覆盖追踪码和点击记录。
- 不在 Phase 0 创建 API、ORM Model、数据库迁移、前端页面或调用真实模型。
- 不提前实现多租户、复杂组织架构、全平台统一同步或大规模分布式任务调度。

## 4. 外部能力与 Mock 边界

| 能力 | 第一版处理方式 | 边界说明 |
| --- | --- | --- |
| 电商平台真实授权 | **Mock** | 只保存平台、账号名称、授权状态和安全元数据，不保存真实凭据。 |
| 平台商品 API | **Mock** | 通过人工录入、文件导入或演示数据提供商品信息；保留适配接口。 |
| 竞品平台数据 | **Mock / 示例数据** | 支持手工录入和有限公开链接解析，不绕过平台限制。 |
| 图片生成 | **第一版允许 Mock** | 仍按异步任务模拟 `pending → running → succeeded/failed`。 |
| 视频生成 | **第一版允许 Mock** | 仍保留失败、重试、取消、超时和任务事件。 |
| 广告平台 | **不真实接入** | 只生成建议和实验计划，所有关键状态由人工确认。 |
| 经营数据 | **手工录入和文件导入** | 支持 CSV / Excel、字段校验、预览、错误明细和部分成功。 |
| LLM | Phase 0 不调用；后续可先 Mock | 业务层依赖统一 AI Provider 接口，不能绑定单一厂商。 |

## 5. 第一版业务边界

- 所有诊断、方案、素材、投放建议、实验、经营数据和报告都归属于具体 `Product`。
- 第一版重点演示一个商品的完整流程，但 `Store → Product` 使用一对多关系，为多商品保留自然扩展空间。
- 多平台通过平台字段和映射对象预留，不在第一版实现实时同步。
- AI 只负责辅助分析与内容建议；用户审核、修改、确认是正式业务步骤。
- 经营分析必须保留输入周期、关联数据和结构化结果，不能只展示一次性文本。

## 6. 第一版最终交付预期

在 Phase 12 完成时，预期交付可运行的前端、后端、数据库初始化与迁移、示例数据、接口说明、导入模板，以及一条可重复演示的单品运营闭环。每项真实能力、Mock 能力和未实现能力必须在界面与文档中明确标记。
